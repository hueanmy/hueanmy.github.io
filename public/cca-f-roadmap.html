Common traps – những bẫy hay gặp trong đề thi
trapFew-shot để enforce tool ordering — ordering là compliance concern, phải dùng programmatic prerequisites, không phải demonstrations
trapSelf-reported confidence cho escalation routing — LLM confidence kém calibrated, model tự tin nhất khi sai nhất
trapRoute mọi workflow sang Batch API để tiết kiệm — Batch không có SLA, blocking workflow bắt buộc phải dùng real-time API
trapTăng context window để fix attention dilution — context size ≠ attention quality, phải split thành per-file passes
trapReturn empty khi subagent fail — phải return structured error context, không được suppress lỗi im lặng
trapCho agent dùng 18 tools — 4–5 tools/agent là optimal, quá nhiều làm giảm selection reliability
5 mental models quan trọng nhất cho kỳ thi
M1Programmatic enforcement vs. prompt-based guidance — khi có financial/compliance consequence → phải dùng code, không dùng prompt (prompt là probabilistic)
M2Tool description là routing mechanism chính — không phải system prompt, không phải function name. Mô tả tệ → model đoán mò giữa các tools
M3Subagent không kế thừa context — mọi thứ cần phải pass explicitly trong prompt, không có shared memory hay automatic history propagation
M4Lost-in-the-middle là design constraint thật — đặt key summaries ở đầu aggregated input, dùng section headers, trim verbose tool outputs trước khi accumulate
M5Batch API vs. real-time là latency decision — Batch tiết kiệm 50% cost nhưng up-to-24h window, không có SLA. Blocking workflow → real-time bắt buộc
